# Claude側への統合手順・連携API仕様

このモジュールは **描画専用** です。ゲームシステム（状態管理・採集・反応・研究・建築判定・セーブ等）はすべて Claude 側が担当し、本モジュールは受け取った状態を表示するだけです。

## 1. 取り込み方法

1. `src/graphics/` フォルダをプロジェクトの `src/graphics/` にコピーする。
2. 依存は `three` のみ：`npm install three`（型は `@types/three`）。
3. アセットは任意。`assets/characters/player-spritesheet.png` を使う場合は、そのURLを `playerSpriteUrl` で渡す。未指定なら内蔵プレースホルダーで動作する。

## 2. 初期化

```ts
import { initializeGraphics } from './graphics';

const gfx = await initializeGraphics(canvasContainerElement, {
  playerSpriteUrl: playerSpriteUrl,   // 任意
  quality: 'auto',                    // 'high' | 'low' | 'auto'
  onContextLost: () => { /* 任意の通知 */ },
});
```

React の場合は `useEffect` 内で初期化し、クリーンアップで `gfx.disposeGraphics()` を呼ぶこと。

## 3. 毎フレーム（または状態変化時）の連携

```ts
// プレイヤー表示状態（座標の正本は Claude 側）
gfx.setPlayerVisualState({
  position: { x: player.x, z: player.z },
  direction: player.direction,  // 'down' | 'left' | 'right' | 'up'
  moving: player.isMoving,
});

// カメラを任意地点へ（null でプレイヤー追従に復帰）
gfx.setCameraTarget({ x: 10, z: -5 });
gfx.setCameraTarget(null);

// 世界の見た目（時刻・天気は演出専用。ゲーム内時刻の正本は Claude 側）
gfx.setWorldVisualState({ timeOfDay: 0.22, weather: 'clear' });
```

## 4. 資源・建築・エフェクト

```ts
// 資源ノードの表示（存在・残量・採取済みの正本は Claude 側）
gfx.updateResourceVisual('tree-001', {
  position: { x: 12, z: -8 },
  type: 'tree',          // 'tree'|'rock'|'herb'|'flowers'|'clay'|'mushroom'|任意
  depleted: false,       // true で切り株・瓦礫などの採取済み表示
  highlighted: false,    // 注目対象のパルス表示
});
gfx.updateResourceVisual('tree-001', null);  // 表示を消す

// 建築物の表示（設置可否・素材・時間の判定は Claude 側）
gfx.addStructureVisual('bldg-001', 'campfire', { x: 3, z: 4 }, 0);
gfx.removeStructureVisual('bldg-001');
// 対応タイプ: workbench / campfire / kiln / smelter / hut / stone-house /
// laboratory / factory / power-plant / research-institute
// 未対応タイプは仮マーカー表示。GLB等への差し替えは
// StructureRenderer.registerFactory(type, factory) で可能。

// 演出（状態には一切影響しない）
gfx.playVisualEffect('discovery', { x: 12, z: -8 });
// 'sparkle'|'discovery'|'levelup'|'splash'|'leaves'|'smoke'
```

## 5. リサイズ・一時停止・破棄

```ts
gfx.resizeGraphics(width, height);  // 通常は ResizeObserver が自動処理
gfx.pauseGraphics();                // 探検タブを離れる等、画面が隠れるとき
gfx.resumeGraphics();               // 画面に戻るとき（再開初回フレームは飛ばない）
gfx.disposeGraphics();              // 画面離脱時
```

`pauseGraphics` / `resumeGraphics` は描画ループの停止・再開だけを行い、
シーンやゲーム状態には一切触れない。どちらも繰り返し呼んで安全で、
`disposeGraphics()` 後の `resumeGraphics` は何もしない。

## 6. 座標系の契約（連携時に要すり合わせ）

- 右手系、Y軸が上。地面は XZ 平面。
- 既定では「ゲーム座標 1単位 = シーン 1単位、原点一致」。
- Claude 側の座標系と異なる場合は、コードを書き換えず `GraphicsOptions.config.coordinates` の `scale` / `origin` で吸収する：

```ts
await initializeGraphics(el, {
  config: { coordinates: { scale: 1, origin: { x: 0, y: 0, z: 0 } } },
});
```

- 地面の高さはモジュール側の地形関数で決まる。建築・資源の `position.y` を省略すると自動で地表に接地する。Claude 側が独自の地形を持つ場合は、この地形関数（`src/graphics/utils.ts` の `terrainHeight`）を連携時にすり合わせること。

## 7. データ所有権（厳守事項）

| データ | 正本（所有者） | 本モジュールの扱い |
|---|---|---|
| プレイヤー座標 | Claude側 | 受け取って描画のみ。書き戻しなし |
| 所持アイテム | Claude側 | 扱わない |
| 資源の採取状態 | Claude側 | `depleted` 等を受けて見た目を変えるだけ |
| 建築物の設置情報 | Claude側 | id/type/座標を受けて表示するだけ |
| ゲーム進行 | Claude側 | 扱わない |

描画補間された座標・アニメーション位相など、表示専用の一時状態のみモジュール内部に保持します。

## 8. キャラクター（主人公）

正式な主人公シートが2名分同梱されています。

- `assets/characters/player-spritesheet-boy.png`（男の子）
- `assets/characters/player-spritesheet-girl.png`（女の子）

どちらを使うか（主人公選択の状態）は Claude 側で管理してください。グラフィック側は表示を切り替えるだけです。

```ts
// 初期化時
const gfx = await initializeGraphics(el, { playerSpriteUrl: boySheetUrl });

// 実行中の切替（主人公選択・着せ替え等）
await gfx.setPlayerSpriteSheet(girlSheetUrl);
```

シート規格：4列×4行（行 = 下・左・右・上、列 = 歩行フレーム）、1セル正方形、足元はセル下端から約11%の位置に統一。自作シートも同規格で差し替え可能です。

## 9. HD-2Dルック（ポストエフェクト）

`GraphicsOptions.postEffects` で有効化します（未指定時は quality が `high` のとき ON、`low` では OFF）。

- ブルーム: ランプ・窓明かり・水面のきらめき等、輝度しきい値（0.82）を超えた部分だけが光ります
- チルトシフト: 画面中央の帯だけシャープに保ち、上下をぼかす HD-2D 特有の「ジオラマ感」
- カラーグレーディング: 温かみのある色調＋彩度補正＋ビネット

モバイル等では `postEffects: false` で従来どおりの軽量描画になります。差は見た目のみで、API や座標系に影響はありません。

また `AssetManager` には石畳・瓦屋根・茅葺き・漆喰壁・木板の手続きテクスチャ生成（`createCobblestoneTexture` 等）が追加されました。デモにはこれらを使った村のセット（`demo/village.ts`、統合対象外）が同梱されています。

## 10. ワールドの見た目（タイルセット系デザイン）

開始フィールドはタイルセット系リファレンスの設計言語で構築されています。

- 地形は段丘状（平らな段＋急な崖際）で、岩肌には地層の縞が入ります。高さ関数は従来どおり `terrainHeight` が唯一の正です
- 土の道（高原→川辺→岩場）が地形色に焼き込まれています。道は見た目のみで、歩行可否・経路はロジック側の管理です
- 岩場の高地には滝（岩組み＋落水シート＋水しぶき＋水煙）と、下部の池があります
- 地平線には雪冠の山並み（遠景レイヤー）が霧越しに見えます
- 道沿いに石段と石垣が配置されています。これらは地形の装飾で、建築物（addStructureVisual）とは別系統です

## 11. 探索カメラと遮蔽フェード（2026-11-06）

探索ホーム仕様（docs/handoff/EXPLORATION-HOME-2026-11-06.md）に合わせ、既定カメラと前景の扱いを変更しました。公開APIの追加・変更はありません。

- 既定カメラ：`viewSize` 26 → 16、`pitchDegrees` 50 → 32（`config.camera`）。主人公の画面占有率は横画面で約10%、縦画面でも約8%以上を維持します（縦画面の視野拡大は最大約1.32倍に抑制）。
- `config.camera.anchorOffset`（任意、既定 0.09）：視点中心を画面上方へずらし、主人公の足元が画面高の約59%に来ます。タップ判定は実際のカメラ変換経由なので表示と一致します。
- 遮蔽フェード：カメラと主人公の視線を遮る樹冠（インスタンシング単位のディザー抜き）と建築物（インスタンス単位の透明度）を自動で薄くします。共有マテリアルは変更しません。ゲーム状態・通行判定には一切影響しません。
- 遠景の山並みを近く・高くし、低視点でも地平線が空白になりにくくしました。チルトシフトのボケ量も弱めています（資源や道の視認性優先）。

## 12. 水面修正・pickGround・安全領域・ワールド作り込み（2026-11-06）

- **川の水面が表示されない不具合を修正**：`TerrainRenderer.buildWater()` の三角形の向きが裏表逆で法線が下向きになっていました。インデックス順を修正し、水面が正しく描画されます（従来「水位より低い土地が水中色に見える」症状の原因もこれでした）。
- **新API `pickGround(canvasX, canvasY)`**：キャンバス内のピクセル座標から、実際に描画されている地表の点を返します。水面に当たれば `surface: 'water'`、地形なら `'terrain'`、どちらにも当たらなければ `null`。表示形状だけの情報で、通行可否は含みません。未対応版との互換のため、呼び出し側は `typeof gfx.pickGround === 'function'` で確認してください。
- **新API `setViewportInsets({ top, bottom, left, right })`**（単位：CSS px）：HUDに隠れる領域を伝えると、カメラが主人公を安全領域内に保ちます。初期値として `GraphicsOptions.viewportInsets` でも渡せます。ズームや追従対象は変わりません。
- カメラ既定値：viewSize 13（主人公の見える高さは横画面で画面高の約10%）、pitch 32°は維持。霧は晴天時 88–195 に遠ざけ、チルトシフトもさらに弱めました。
- ワールド表現：森は群生＋空き地の構成にし、細身の樹形を追加。岩は角ばった形状＋沈み込み＋岩場への集積に変更し、樹冠と同じ仕組みで遮蔽フェードの対象にしました。地面には土のムラを追加し、道の上には草・低木・倒木を置かないようにしました。地形の外周には遠景の地面（スカート）を敷き、低視点でも空白が見えません。

## 13. 採取ノードの状態表現・制作情報・画風テクスチャ（2026-11-06）

### 状態の契約（updateResourceVisual）

ノードの存在・位置・状態は全てゲーム側が正です。描画側は受け取った状態を
そのまま描き、同じ id＋位置には常に同じ見た目を返します。装飾として別乱数で
生やした「採取できそうな木・岩」はワールド側に置いていません（環境の木・岩は
景観専用で、採取対象は必ずノードとして渡してください）。

- `phase: 'reacting'`（任意、既定 'idle'）：採取中の反応。木は揺れ、岩は小刻みに
  震えて明滅し、草は揺れます。表示だけの演出で、phase を戻せば姿勢・スケールは
  完全に元へ戻ります。採取の開始/終了・成否はゲーム側が決めます。
- `depleted: true`：木→切り株（年輪付き）、岩→破砕した残骸、草/花→刈り跡
  （短い株のある円形パッチ）。`branch`（落ち枝）/`pebble`（小石）の depleted は
  裸地です。回収済みの非表示は従来どおり `visible: false` か id の削除で。
- 描画側から復活することはありません。状態が変わるまで depleted は維持されます。

新タイプ：`branch`（落ち枝：地面の枝2本）、`pebble`（小石：小岩3個）。

### 制作情報 API

`gfx.getResourceVisualSpecs()`（モジュール index からは `RESOURCE_VISUAL_SPECS`）
が、タイプごとの `{ footprintRadius, trunkRadius?, height, depletedForm }` を
返します。scale 1・原点＝接地点での寸法です（実寸は state.scale 倍）。
幹半径・占有半径は見た目通りの値で、衝突の最終判定はゲーム側にあります。

| type | footprintRadius | trunkRadius | height | depletedForm |
|---|---|---|---|---|
| tree | 1.15 | 0.26 | 3.6 | stump |
| rock | 1.0 | — | 1.15 | rubble |
| herb | 0.35 | — | 0.6 | cut-patch |
| flowers | 0.35 | — | 0.55 | cut-patch |
| clay | 0.65 | — | 0.4 | none |
| mushroom | 0.32 | — | 0.65 | none |
| branch | 0.5 | — | 0.16 | none |
| pebble | 0.32 | — | 0.2 | none |

### 画風テクスチャ

環境とノードで同じ手続きピクセルテクスチャを共有し、単色プリミティブ感を
抑えました（`AssetManager.createBarkTexture / createFoliageTexture /
createRockCrackTexture`）。幹には樹皮、樹冠には葉の斑、岩には割れ目。
環境の広葉樹には枝インスタンスを追加し、幹＋枝＋葉のまとまりとして読めます。

### 実験器具アセット（研究室→実験台）

`assets/lab-apparatus/` に器具セット（bbmodel / glTF / 透過スプライト /
テクスチャ）を追加しました。装置と液体・炎は別レイヤーで、段階（原始＝土器・
石、ガラス〜、近代＝金属）に対応します。詳細と対応表は同フォルダの README。
AI生成の研究室背景は使わない前提です。

## 14. 自然物の造形刷新とキャラクター静止契約（2026-11-06）

### 自然物（描画専用、API変更なし）

- 草は単体の円錐から、透過切り抜きテクスチャの十字面「草むら」に変更。
  高さは主人公の足首〜すね程度（約0.3〜0.55）、約12%だけ膝丈の高い株。
  分布はノイズによる群落マスク＋疎な下地で、全面均等ではない。
- 茂みは3つの瘤の集合＋葉カード（透過切り抜き面）で構成。木の樹冠も
  頂点ジッターで輪郭を崩し、葉テクスチャに陰影の斑を入れた。
- 落ち葉・土の表現は、輪郭のはっきりした単色ポリゴンを廃止し、
  柔らかい斑点テクスチャのパッチに変更。木・岩・茂みの根元には
  暗い土の接地ディスクを敷き、接地感を出している。
- 岩は頂点カラーで根元側を暗く＋苔色に寄せ、地面への埋まりを表現。
  幹は根元を太くした（根張り）。

### キャラクターの静止（重要）

- `moving: false` の間、歩行フレームは進みません。最後に向いていた
  方向の「直立コマ」に固定され、上下動（ボブ）も止まります。
  歩行サイクルの時計自体が止まるので、再開時は止めた位相から続きます。
- 直立コマは男の子・女の子の両シートを実物確認して **列0** と特定
  （全方向行で足を揃えた直立ポーズ。列1・3が歩幅、列2が通過ポーズ）。
  シートを差し替える場合はこのレイアウトを維持してください。
- `character.idleFps` は廃止扱い（設定互換のため残置、未使用）。
- **注意**：グラフィック側は `moving` を全面的に信頼します。壁に
  押し付けて位置が変わらないのに `moving: true` が届くと、その場で
  足踏みします。実移動量がゼロのときは `moving: false` を送って
  ください（カメラ移動や表示補間を歩行判定に使うことはありません）。

## 15. GPT生成素材による森林改修（2026-11-06）

素材の正本はリポジトリの `assets/gpt-nature/`（原画・加工済み・対応表・
加工ツール）。描画モジュールは `src/graphics/gptTextures.ts`（データURI
同梱、約0.9MB）に焼き込んで使うため、追加のファイル読込みは不要。
いずれかの画像がデコードに失敗した場合は手続きテクスチャへ自動で
フォールバックする（描画が止まることはない）。

### 使い方（見た目の割当て）

- 地形の土台テクスチャ = A草地の抑制版（彩度・コントラストを落とした派生）。
  地形の頂点カラー（道・岸・林床のブレンド）は従来通り。
- 地面デカール（柔らかいαマスクの円形パッチ、四角い境界なし）:
  林床=落ち葉テクスチャ、川岸=砂利、道の縁=土。
- 木: 幹テクスチャは樹皮（広葉樹=深溝／白樺=白樺）。白樺は独立した
  亜種として約2割出現し、幹が細く白い。樹冠は瘤＋葉カード（Dシートの
  葉付き枝スプライトを樹冠表面に8枚/本）。茂みは瘤＋低木カード。
- 草: Eシートの3種（短い草／広がる草／枯れ草）を十字面で配置。
  枯れ草は道沿いと乾燥ノイズ域、広がる草は草原の芯。花は白・黄・紫の
  スプライト株。シダはEのシダ株。
- 岩: 層状岩テクスチャ（標準）と苔岩テクスチャ（川辺・林内）。
  高地の大岩は粘板岩寄りの青灰色にインスタンス色で寄せる。
- 単体スプライトは縮小時のα侵食に弱いため、草花スプライトのαを
  加工段階で1px太らせ、alphaTestは0.35に下げてある。

### 採取ノード（ID・位置・状態契約は§13のまま）

- 木ノード: 樹皮テクスチャ＋葉カード4枚。採取済み=切り株スプライト。
- 岩ノード: 層状岩テクスチャ。採取済み=瓦礫スプライト。
- 草ノード: 野草スプライトの十字面。花ノード: 白/黄/紫のスプライト
  （IDハッシュで決定的に選択）。採取済み=刈り跡スプライト（平置き）。
- 枝・小石ノード: Fシートのスプライト（カメラ方位=yawへ正対する立て札式。
  カメラは周回しない前提）。スプライト小物は太陽の反対側で真っ黒に
  ならないよう、テクスチャ色の弱い自己発光（0.38）を付けてある。
- `RESOURCE_VISUAL_SPECS` の branch / pebble の height をスプライトの
  実寸に合わせて更新（0.78 / 0.49）。footprint・原点（接地点）は不変。

### 注意

- ゲーム本体の単一ファイルは約2.2MB→約3.1MBになる（素材同梱分）。
- 地面タイルは対称クロスフェードで継ぎ目を消しているため、タイル端で
  模様が鏡像になる。頂点カラーの大域変化とデカールで目立たせない。
- 未使用の素材（wood_grain、bark_moss、rock_slate、cliff_dirt、
  prop_bundle、prop_flint、leaf_fern）は予備として assets に保管。

## 16. Claude未解決事項への対応（2026-11-06）

CLAUDE.md「Muse への依頼事項（未解決）」と NATURAL-OBJECTS-CONTRACT への回答。

### pauseGraphics / resumeGraphics（依頼1）
本流チェーン（gpt-forest の上）に正式取り込み済み。§5 のとおり。
内部 stopLoop / startLoop の直接呼び出しは不要になった。

### GraphicsOptions.decor（契約 §5.1・依頼8）
初期化オプション `decor: { trees, rocks, logs, pebbles, shrubs }` を追加。
false の家族は描画側の装飾として一切生成しない（ゲーム管理の自然物と
二重描画しないため）。Claude の提案パッチと同じ API 形状で、現行コードに
合わせて実装した。草・シダ・落ち葉・地面デカール等の細部装飾は対象外。
未指定は全て true（従来表示）。

### 自然物のバッチAPI（契約 §5.3）
`gfx.setNaturalObjects(list)` / `gfx.updateNaturalObject(id, state)` を追加。
setNaturalObjects は一括 upsert に加え、この口で渡したのに今回のリストに
無い ID を除去する（近傍のストリーミング用）。updateResourceVisual で
管理する ID は除去対象にならない。描画の内部表現は従来のノード単位で、
種類別インスタンス化は未実施（今後の性能課題として残す）。

### ノードの遮蔽フェード（依頼9・§7-3）
ResourceRenderer にも環境・建物と同じ遮蔽フェードを実装。木・岩・鉱石・
やぶのノードがカメラ→主人公の視線を遮ると不透明度が下がる（最小0.22、
材質はノード専用なので他へ漏れない）。

### highlighted の変更（依頼9・§7-4）
選択強調は「ノード全体の発光パルス」を廃止し、足元の輪（footprint×1.3、
黄色、穏やかな明滅）に変更した。樹冠が光って主人公や名札を隠すことはない。

### 資源タイプ追加（依頼2・契約 §5.2）
- `water` 水源：石の縁取りのある泉の池。`oil` 原油：黒い光沢の染み出し＋黒岩。
- `ore` 鉱石：層状岩＋結晶（石英白・琥珀）。代わりに通常の `rock` から
  結晶を外した。景観の岩に付いていた装飾結晶も廃止し、結晶＝鉱石ノードに統一。
- `grass` 草むら（採取用）・`bush` やぶ の専用タイプを追加。採取後は刈り跡。
- バリアント：`natural.variant` を読む。'basalt' の岩は黒岩、'flint' の
  小石は暗く表示。spec に water/oil/ore/grass/bush を追加。

### 構造物タイプ追加（依頼6・依頼4）
- `waterwheel` 水車（回る）、`steam-engine` 蒸気機関（フライホイール回転）、
  `distillation-tower` 精留塔、`drilling-rig` 掘削やぐら を追加。
- `bridge` 橋：ローカル +X が橋の長さ方向（全長3.6）、幅1.6、甲板上面は
  原点から端で約+0.49・中央で約+0.65。通行可否と歩行高度の扱いはゲーム側の
  判断（描画は形だけを提供する）。置くときは川を横切る向きに rotationY を。

### 水中の色（依頼5）
原因は水面が描かれていなかったこと（world-polish で修正済み・統合済み）。
現行ビルドで川を確認したところ、水面の下に川底が見える形で意図どおり。
対応完了として扱ってよい。

### アイコン（契約 §6）
`assets/icons/` に Claude 指定の名前・形式で書き出した：
lab / craft / book / tech / log / map / home / settings（96×96 WebP 透過）。
`menu` 用の原画アイコンがシートに無いため未収録（受け口の絵文字フォール

### バイオーム（依頼3）
洞窟・鉱山・火山・海岸・油田は未対応。世界のレイアウトと地域の開放設計
（ゲーム側の地域管理）に直結するため、描画側だけで先行実装せず、配置の

配置場所・広さ・開放条件、GPT 側の素材シート（地形・岩・固有物）。

## 17. 水表現の刷新と素材一式（2026-11-06、feature/graphics-item-icons-water）

### 水のレイヤー構成（TerrainRenderer）
水は「一枚の絵」ではなく3層で構成する。
1. **川底レイヤー**: 川底に沿うリボンメッシュ（新設 `Riverbed`）に
   小石・砂・苔のプロシージャルテクスチャ（AssetManager
   `createRiverbedTexture()`）を貼り、水深の浅い所では水面を通して
   川底が見える。水面より上に来る部分は岸の下へ潜らせて隠す。
2. **地形の水際**: 頂点色に「濡れ土バンド」を追加（水位〜+0.34 の範囲を
   暗く湿った土色に）。水中の床色にも砂／湿砂のノイズ変化を付けた。
3. **水面レイヤー**: リボンを横9点に細分化し、各頂点に実水深
   （waterLevel − 地形高）と流れ方向を持たせた。シェーダーは
   - 色・透明度を水深でグラデーション（浅瀬は川底が透け、深みで青く）
   - 波紋はドット調の短い線を2層（異なるスケール・速度）で流れ方向に
     スクロール。各ダッシュはセル単位で回転・濃淡が変わり、規則的な
     繰り返しや一様なスクロールに見えないようにしてある
   - 泡は水深が浅い帯にだけ、ダッシュノイズで途切れた形で発生
     （岸線は水深フィールド由来なので不規則）
   - 太陽のグリントは深い部分にごく控えめに点在。全面の白い反射や
     ゼリー状のうねりは付けていない

### 調整パラメータ（GraphicsOptions.config.water）
`shallowColor / deepColor / shallowAlpha / deepAlpha / deepDepth /
rippleScale / rippleSpeed / rippleScale2 / rippleSpeed2 /
rippleStrength / foamDepth / foamStrength / glintStrength`
既定値は config.ts の DEFAULT_CONFIG.water。ゲーム側から上書き可能で、
コード変更なしに調整できる。

### 品質連動
quality が 'low' では第2波紋層を無効化しグリントを 0.4 倍に落とす。
スマホでは従来どおり quality の解決結果（'auto' の端末判定）に連動する。

# 実習・試験の文章監修（2026-11-14）

実装正本は space-data.js、補足・修正文は space-science.js、画面は space-ui.js。変更不要な項目は維持と明記する。下記は現実の装置の認証ではなく、ゲームの学習課題である。

|項目|今の文 → 採用する文|理由・判定|
|---|---|---|
|switch|導体なら点灯、絶縁体なら消灯 → 維持|両方を試してから点灯させるので、偶然の正答だけにならない。材料の状態による違いは省略。|
|transistor|電流で切り替える素子 → 電気信号で切り替える素子。小さな制御信号で別の回路の状態を切り替える|電流制御だけが全素子に共通するという誤解を避ける。実習は入力1で出力1になる模擬スイッチ。|
|gates|ORはどちらか1 → ORは少なくとも片方が1なら1|両方1でも1になることを明記し、排他的ORとの混同を避ける。全真理値を試す。|
|adder|0011 + 0010 = 0101 → 維持|桁と結果が一意。十進数表示も併記する。|
|memory|入力を変えても保存した値は残る → 維持|書込みと読出しを分け、入力欄の表示を記憶と混同させない。|
|architecture|演算は計算、制御は順番、記憶は保存、入出力は外との窓口 → 維持|4役の対応を一意にする。実物のCPU設計図ではない。|
|program|LOAD 2 → ADD 3 → STORE → OUT。飛行制御ではない → 維持|小さな教育用命令列で結果5を確認。ロケット誘導には接続しない。|
|sensors|架空の環境値を読み、異常を表示する → 維持|実測値・実機の運転基準と区別。回答は表示された異常機能に対応する。|
|power|電源と配線／配線 → 維持|部品と先行条件を確かめ、問いに合う機能を選ぶ模擬点検。|
|computer|計算機自己診断／記憶 → 維持|計算機の役割の復習。実機の網羅的な診断ではない。|
|radio|通信確認／通信 → 維持|情報のやり取りという目的を示す。電波の製造・運用条件は扱わない。|
|suit|宇宙服の機能／気密 → 維持|組立・装着・先行試験が必要。気密だけで宇宙服全機能を保証する意味ではない。|
|life|生命維持とカプセル／空気再生 → 維持|供給だけでなく二酸化炭素除去の役割を確認。他機能も組立条件に含む。|
|uncrewed|無人模擬飛行／模擬 → 維持|実飛行計算を行わない。先行試験と全組込部品を条件にする。|
|final|総合点検／全項目 → 維持|全条件の再確認。部品交換・移設後は以前の合格を流用しない。|

試験は機能名を選ぶ短い課題で、確率故障や全損はない。合格は現実の有人飛行の安全性を意味しない。UI実行・誤答拒否・先行条件・試験失効は自動検証する。

根拠：[MIT Computation Structures](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2017/)、[EIA 電池と回路](https://www.eia.gov/energyexplained/electricity/batteries-circuits-and-transformers.php)、[NASA 宇宙服](https://www.nasa.gov/humans-in-space/what-is-a-spacesuit/)、[NASA ECLSS](https://www.nasa.gov/reference/environmental-control-and-life-support-systems-eclss/)。確認日2026-11-14。機能の説明の根拠であり、ゲームの合格判定の認証ではない。

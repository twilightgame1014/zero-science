# ゲーム基本仕様 — ゼロからの科学 〜石と水と木から〜

更新日: 2026-11-06  
対象: ゲームの目標と確定した設計原則。**実装済み**の詳細はコード・テストで確認する。

## 1. ビジョン

自然界にある石・水・木・鉱物・植物などの資源を採取し、科学的な発見と工作を繰り返して現代文明を再構築する、学習型の科学シミュレーションゲーム。

- 最初の所持品と研究設備はゼロ。自然界の資源から開始する。
- プレイヤーは科学的な知識を探求し、実験・精製・製錬・製作をつなげて新しい技術に到達する。
- 実在する科学的な性質と製造原理に基づく。危険な工程は教育的で安全な表現に抽象化する。
- 初学者でも序盤から発見できる一方、長期的には大量の物質と製品のコレクションを目指せる。
- 一本道のストーリーや固定の最終エンディングを中心にはしない。
- 戦闘・空腹・睡眠のようなサバイバル要素は中心機能にしない。

## 2. プレイヤーの基本ループ

1. **探索** — フィールドを歩き、地域の環境と採集可能な自然資源を見つける。
2. **採取** — 道具や探索度に応じた資源を得る。希少な発見もある。
3. **工作** — 道具や設備を製作する。機械的な組立と化学・物理プロセスは区別する。
4. **実験** — 原料、装置、操作を選び、登録された科学的に妥当な結果を得る。
5. **発見** — 初めて取得した物質・道具・設備を図鑑に記録する。
6. **発展** — 新しい材料・設備を使い、より高度な研究や地域に挑戦する。
7. **省力化** — 既知の作業を効率化・自動化し、未知の研究に集中する。

序盤は短い試行錯誤で小さな成功が連続する。後半は複数分野をまたぐ設備・中間体・材料の発展関係を解く。

## 3. 現在の実装と目標を区別する

### リポジトリで確認できる実装構造（2026-11-06時点）

- `src/game/data.js`: `items`、`ops`、`procs`、`crafts`、`regions`、`stages`、`eras`、`missions`。
- `src/game/engine.js`: 採取・探索進捗・自動採取・実験判定・工作・発見・状態・セーブ移行・テスト。
- `src/game/ui.js`: 研究室・探索・工作・図鑑・地図・履歴などの画面とHD-2D連携。

- `tests/`: エンジンテスト、探索・発見シミュレーション、ブラウザ結合テスト。

上記はソース上の存在確認であり、全環境での動作保証ではない。

## 4. アイテムの分類

天然資源、元素、無機・有機化合物、鉱物、天然混合物、金属・合金、高分子、材料、部品、完成品、道具、研究設備を区別する。分類は複数タグを許す。

- 化合物には可能な限り組成・物性・科学上の分類を持たせる。
- 混合物や材料の品質を、単一の「純度」だけで表さない。
- 完成製品は構成部品・材料・組立・利用可能な設備に紐づける。
- IDは永続的な参照キー。表示名を変えても既存セーブを壊さない。

## 5. 実験・工作・技術ネットワーク

現行の実験は、投入アイテム集合・操作・使用設備・補助道具などを登録済みプロセスと照合する方式。未登録の組み合わせでは原料を減らさない。

将来目指す拡張は、装置性能、温度・圧力・時間、収率、生成物の品質、適用可能な一般操作規則の導入。ただし未知の化学反応を根拠なく生成しない。

単一の完成品に複数の妥当な到達経路が存在するときは、製造ルートとして並存させる。科学の進歩を固定されたレベル解放だけで表現しない。

## 6. 図鑑と教育

図鑑は長期プレイの主要な到達目標。発見済み／未発見を区別し、研究の進行に応じてヒントを提示する。

- `kid`: 初学者向けにやさしく説明
- `more`: 背景・科学的な詳細
- `why`: 実験による変化の説明
- `how`: 工作の説明

将来的に、出典、別製法、最高品質、製造履歴、製品への用途などを段階的に拡張する。**現時点で全項目が完備しているとは扱わない。**

## 7. 画面・操作

- 研究室を中心画面とし、探索フィールドと相互に行き来できる。
- HD-2Dの自然環境：3D地形・建物と2Dキャラクターの組み合わせ。
- PC・スマートフォンで読みやすいUI、タッチ操作、適切な表示負荷。
- 発見、進捗、装置の利用可否、必要資源を分かりやすく示す。
- 実験の視覚演出は、実際に起こりうる現象と整合させる。

## 8. 長期的な収録目標

新しい元素・化合物・医薬品・工業製品を継続追加できるデータ構造を目指す。数万種類という収録数は**構想上の目標**であり、実装済み数や到達可能性を保証しない。

外部データを取り込むときは化学物質の登録と「ゲーム内に製造経路があること」を分けて管理する。

## 9. 完了の判定基準（機能ごとの共通観点）

- 自然資源から新しい対象に到達する経路がある。
- 必要設備・道具・操作の条件が正しい。
- 科学的な説明と対象の種別が一致する。
- 在庫・発見履歴・セーブ・ロードが一貫する。
- 初学者向けの手順が分かりやすく、PC／スマホで操作可能。
- テストとレビューの結果をPRに残す。

実装の詳細や優先順位は `docs/DEVELOPMENT_ROADMAP.md` を参照。

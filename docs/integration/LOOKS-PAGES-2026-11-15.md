形の値は `town-construction.json` の正式値の写し。`tests/construction-looks.test.mjs` が同じ値かを検査する。

### 働きは変えていない
- 働き・工程・資材・返却表・分類（街の数え方）は、元の設計図の物をそのまま使う（`CONS.view` が形と描画の種類だけを差し替える）。
- 次のことはしていない：
  - 上位設備にする・必須設備にする
  - レシピの設備の条件を変える
  - 保管の量を増やす
- 同じ働きの建物を複数建てても、作れる量は増えない（既存の決まり。テストで確かめた）。

### 工房の建物の操作点
- Muse の値では、作業台の前の操作点 (0,−0.4) が建物の中にある（前面が開いた建物）。
- ゲームの当たり判定は占有範囲の四角（壁）なので、中へは入れない。
- そこで操作点は使わず、入口の前があいていることだけを置くときに確かめる。設備は、完成した建物があればどこからでも使える（従来どおり）。
- 中へ入れるようにするには、当たりの形を「コの字」などにする必要がある。今の当たり判定（円と回転した四角だけ）にはない形なので、今回は入れない。

### 保存と以前のセーブ
- 新しく建てるときに選んだ外観だけ、`S.cons.inst[id].look` に保存する（セーブ v6 のまま。項目を 1 つ足しただけで、形式の変更はない）。
- 以前のセーブの建物には `look` がない。従来のモデル（hut・workbench）・位置・向き・当たりのまま。
  - 読み込み時に新しいモデルへ置き換えない。
  - v5 からの移行で建つ倉庫も従来の形。
- 知らない外観（壊れたセーブなど）は標準の外観に戻す。
- 既存の建物の外観を変える機能は作っていない（今回の必須ではない）。
- この版の前のゲームで新しい外観の建物を含むセーブを開くと、`look` は無視されて従来の形になる（前方の互換はない）。

### 置く判定・移動・撤去
- 予定地・移す・資材を返して移す：外観の正式の占有範囲で判定する。対象は次のとおり：
  - 傾斜
  - 木や岩
  - 道
  - ほかの建物
  - 採取地点
  - 発射場の予約範囲
  - 入口の前
- 置けないときは理由を出して止まる。
- 解体は元の設計図の返却表どおり。

## 3. GitHub Pages：main 限定の自動公開（`.github/workflows/pages.yml`）
| 条件 | どう守るか |
|---|---|
| main への push で公開 | `on.push.branches: [main]` |
| feature への push では公開しない | push のきっかけは main だけ。feature への push で動くのは `test.yml`（公開しない）。このブランチの push で確かめた（Actions run 43667070247 は「テスト」だけ） |
| 手動実行でも main 以外は公開しない | すべてのジョブに `if: github.ref == 'refs/heads/main'` |
| PR から公開しない | きっかけに `pull_request` がない |
| 公開する SHA で test・typecheck・build・e2e が合格 | build ジョブで 1 回だけビルドし、typecheck・npm test・`version.json` の SHA を確かめる。その dist を artifact にして、verify ジョブ（6 つ）が取り出して e2e。deploy は `needs: [build, verify]` |
| 公開する成果物＝検証した同じビルド | build ジョブで `upload-pages-artifact` した物を deploy-pages が公開する。e2e も同じ dist（作り直さない） |
| 失敗したら公開しない | どれかが失敗すると needs で deploy は動かない。verify は `fail-fast` |
| 古い版が後から公開されない | `concurrency: pages-main`（実行中の公開は止めない。待っている古い実行は新しい実行に置き換わる）。さらに公開の直前に、この SHA が main の先端か GitHub API で確かめ、違えば公開しない |
| 配信中の SHA がわかる | `dist/version.json`（sha・bytes・run）。ゲームの画面には出さない |
| 同じ検証を重ねない | `test.yml` は main への push では動かない（`branches-ignore: [main]`）。PR とほかのブランチでは今までどおり |

`tests/pages-workflow.test.mjs`（npm test）がこれらの条件を検査する。
- 実際の公開の動作は GitHub の上でしか確かめられない。
- main へ入れる前は「未確認」。

### オーナーにお願いしたいこと（このセッションからは設定を変えられない）
1. **`github-pages` の環境に、公開できるブランチの制限を付けていただきたい。**
   - 2026-11-14 の公開（run 43611668145）は、`feature/pages-auto-deploy` の手動実行から通った。今はどのブランチからでも公開できる状態になっている。
   - 制限の付け方：Settings → Environments → github-pages → Deployment branches を main だけにする。
   - こうすると、古いワークフローが残ったブランチ（dfb7265 の `on: push` は全ブランチ）から公開されることも止まる。
2. **`feature/pages-auto-deploy` ブランチの扱い。**
   - このブランチに push すると、そのブランチのワークフローで公開される。
   - 消すか残すかはオーナーの判断（私は消していない）。

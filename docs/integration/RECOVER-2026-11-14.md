## 発射サイト全体の予約範囲
- **変えたこと**：`ui.js` の `syncStructColliders` がサイト全体（`D.space.siteSpec` の 18×18、向きつき）を `space-site:area`（`walk:true`）として渡す。
  - 建物と道は置けない。
  - 歩行・押し出し・経路には入れないので、搭乗口への道筋は設備ごとの形のまま。
  - 予約はセーブに書かず、発射サイトの位置から毎回作る。
- **置き直し**：`nature.js` の置き場所の判定の ignore を前方一致にした（`struct:space-site` と `struct:space-site:*`）。発射サイトの置き直しで自分の予約と設備の形を数えない。
- **指摘の再現**：基準 34dd168 の画面（偽の描画、射点 (-150,90)・向き 0°）では、(-157,87) の作業台はもともと拒否された。理由は「ほかの建物と重なる」で、発射台 16×16 と置き場所の余白に当たる。発射台のまわりの幅 1 の帯（小さな石どうろう・植木鉢）も同じく拒否された。指摘の数値の条件（設備の当たり判定が登録されていない状態など）は確かめられなかった。
  - このため予約は「設備ごとの形に頼らない保証」として入れた。テストで、設備の形を空にしてもサイトの中に建てられないことを確かめる。
- **検査**：`tests/space-reserve.test.mjs`（26 件、`npm test` に入れた）
  - 向き 0°・45°・90°で：設備の隙間に置けない、範囲の外は止められない、道を敷けない、搭乗口から中へ歩ける（経路あり）、置き直せる
  - 保存して読み直しても同じ
  - 設備の形が無くても置けない
  - 発射サイトの前は置ける

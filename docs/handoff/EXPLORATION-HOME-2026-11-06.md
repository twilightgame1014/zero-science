# 探索ホーム化・低視点HD-2D 改修仕様
更新：2026-11-06。状態：実装依頼仕様（実装済みを意味しない）。

## 今回の決定
探索フィールドをゲームのメインホームにする。研究室・工作・図鑑・技術・記録は下部タブからパネルとして開く。探索を作り込み、主人公が小さすぎる現在の見え方を改善する。追加要望として、見下ろしが強すぎるカメラを低くし、参考画像のようにキャラクター・建物の正面と地形の奥行きを見せる。
Claudeはゲーム本体・UI・入力・統合、Museは描画・カメラ・環境・視覚効果を担当する。

## 現行コードから確認した出発点
- src/game/ui.js：U.tab="lab"で起動。setTab/renderで画面を切替。in3Dやキー入力、探索更新にU.tab依存がある。
- src/graphics/config.ts：正投影カメラ viewSize=26、pitchDegrees=50、yawDegrees=45、followDamping=5.5。キャラ寸法1.7×1.7。
- src/graphics/CameraController.ts：pitchは水平面から下を向く角度。距離90。縦画面で視野高を最大1.9倍に広げる。
- 正投影なので、カメラを物理的に近づけるだけではキャラは大きくならない。viewSizeと実際の描画領域を調整する必要がある。
- src/game/ui.jsは投影・地面への入力変換を行う。低視点化時に高さのある地形でのタップ精度を再確認する。
- 旧HANDOFF-TO-CLAUDE.mdの「研究室背景をメインにする」は今回の探索ホーム方針で置き換える。既存の研究室背景は研究室パネル内で引き続き使う。

## 見た目の目標とカメラの初期調整値
参考：ユーザーが会話に添付した草原と街並みの2枚（画像本体はリポジトリ未登録）。構図・俯角・奥行きの参考専用。画像にある人物、敵、建物をそのままゲーム素材として使わない。
- pitchDegrees：まず32度。28〜36度の範囲で実画面を比較し決定する。画像から実測した角度ではなく調整開始値。
- yawDegrees：まず45度を維持し、移動方向や既存地形との整合を守る。
- viewSize：横画面はまず16（調整範囲14〜18）。縦画面でも主人公が極端に縮まないようfrustum補正を見直す。
- followDamping：まず5.5を維持。移動開始・停止・地域遷移で揺れや遅れを確認する。
- スプライトの透明余白を除く人物の高さを測り、横画面では探索表示領域の約9〜13%を目安にする。縦画面は移動可能範囲との両立を優先し約8〜12%から調整する。
- 主人公の足元は探索表示領域の中央〜やや下（高さ55〜62%）を目安。HUDや下部タブに隠さない。
- まず正投影を維持。遠景・霧・段差・重なりで奥行きを作る。低い視点でも地平線の表示を無理に強制せず、マップ端の空白や地形の裏側を見せない。
- 人物と採取地点は鮮明に保つ。ボケ・ブルーム・夕景は補助。暗すぎて資源を識別できない見た目は禁止。
これらの数値は完成条件ではない。PCとスマホの実画像・操作で最終判断する。

## 探索ホームと操作
1. 初回開始後・再読込後は探索ホーム。既存セーブを保持し、現在地を不必要に初期化しない。
2. フィールドを主表示にし、上部は文明段階・目標・必要な状態をコンパクトに。長い説明は開閉できる形へ。
3. 下部に「探索／研究室／工作／図鑑／技術／記録」。探索でパネルを閉じる。閉じるボタンも用意する。
4. PCではサイドまたはオーバーレイ、スマホでは読みやすいシート。研究室の材料・設備・操作・結果を欠落させない。
5. パネル表示中は移動・採取入力を止める。押下キー・スティック・移動予約も解除し、閉じた瞬間の勝手な移動を防ぐ。背景の描画継続は負荷に応じる。
6. WebGLキャンバスをタブ操作ごとに破棄・再生成しない。戻ると座標・カメラ・資源状態が維持される。
7. 図鑑の詳細モーダルや初回案内をパネルより前に表示。Escapeとフォーカス復帰を整理。入力欄のキーで移動しない。
8. 仮想スティック、採取ボタン、下部タブ、セーフエリアを重ねない。主操作のタップ領域44 CSS px以上を目安とする。
9. WebGL失敗時の2D探索と既存セーブの書出し・読込みを維持する。
10. 目標「そこへ行く」、記録の「もう一度」、技術マップへのリンクも新しいパネル遷移へ統一。

## 探索環境の作り込み
- 木の幹・葉・草・岩・岸・段丘・道を読み分けられる素材と密度にする。通れる道と資源を装飾に埋もれさせない。
- 低視点で手前の木や建物が主人公を隠す場合、遮蔽物だけを段階的に薄くする等の描画対応を行う。離れたら復帰。共有マテリアルの変更で全森林を透過させない。
- 表示側の装飾を追加しても当たり判定や通行可能性を勝手に変えない。橋・水域・崖の通行規則はClaude側と契約を合わせる。
- 既存の採取可能資源は、見た目・ハイライト・選択位置・ゲーム上のノードIDを一致させる。
- 地域の解放条件、採取結果、科学データ、セーブIDを見た目の都合で変更しない。

## 完了判定
- 1366×768、390×844、844×390を最低限確認。PC・スマホで同じ低視点の意図が保たれる。
- 改修前後を同じセーブ・位置・向きで撮影。森林、川岸、岩場、拠点を確認。遮蔽の前・中・後も撮影。
- 移動、タップ移動、近接採取、地域遷移、研究室での実験、工作、図鑑、技術、記録、セーブ復元が動作する。
- パネル開閉20回でもキャンバス・イベント・描画ループが増えず、入力抜けや背景誤操作がない。
- 低視点でもクリック地点と歩行先が高さのある地形で一致。地形の裏側・空白・足の浮き・スプライトの潰れがない。
- npm test、npm run typecheck、npm run build、npm run e2eを実行。既存e2eは偽描画なので実WebGLでの視覚・入力確認も必須。
- 実端末を確認できない場合はエミュレーションと明記し、FPSの実測値を捏造しない。
- 変更ファイル、確定カメラ値、画面比較、テスト結果、残課題を報告する。

## GPT画像素材の扱い
新規素材が必要なら、Museが用途・透過要否・寸法・視点・タイリング要否・必要枚数をリスト化する。GPTで生成してユーザーに提示したものを取り込む。参考スクリーンショットをテクスチャに流用しない。まず既存素材とカメラで構図を確定し、必要な素材だけ追加する。

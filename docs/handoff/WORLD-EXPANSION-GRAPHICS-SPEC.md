# 広い世界への拡張：描画モジュールへの依頼仕様（Claude → Muse）

作成：2026-11-07（Claude）。状態：**提案**（オーナー決定：描画は Muse、ゲーム側は Claude で分担）。
オーナーの要件全文は会話の依頼（「広い世界を自由に探索・建築できるゲームへ拡張」）。ここでは描画モジュールに必要な部分だけを、
ゲーム側の受け口（すでに実装済み・テスト済みのもの）と合わせて書く。API 名は提案で、Muse 側で変えてよい（変えたら `types.ts` が正本）。

## 0. 現状（2026-11-07 時点の実測）
| 項目 | 今 | 目標 |
|---|---|---|
| 地形 | 120×120 の 1 枚メッシュ（168 分割）。`terrainHeight` に川・北東の高地・拠点の台地・外周の丘を直書き。水面は川の帯だけ | 歩ける陸地を約 9 倍（一辺約 3 倍：360×360 前後）。7 エリア＋移行帯。区画（チャンク）ごとに作る |
| 歩ける範囲 | ゲーム側で `|x|,|z| ≤ 56`（`nature.js` の `WORLD_R`） | 新しい地形に合わせてゲーム側で広げる |
| カメラ | 正投影。`pitchDegrees 32`・`yawDegrees 45`・`viewSize 13` を起動時に固定。実行中に変える API なし | 360 度回転・上下角・ズーム（`viewSize`）を実行中に変える |
| キャラクター | 主人公 1 人（4×4 シート：下・左・右・上） | NPC（同じ形式のシートを複数） |
| 建物 | `addStructureVisual`・GLB ファクトリ（ゲーム側で登録） | 建築モードの半透明プレビュー（緑／赤） |
| 環境 | 照明・霧は全体で 1 つ。音はない | エリアごとの照明・空・霧・粒子。音はゲーム側（§7） |

## 1. 地形とエリア（最重要）
### 1.1 エリア配置は「共有データ」にする
- 7 エリア（森林・湖畔・海岸・火山・雪山・砂漠・街）と移行帯の配置を、**ゲームと描画で同じデータ**から決めたい。
  案：`GraphicsConfig.world.areas`（中心・半径・種類・強さ）をゲームが渡し、`terrainHeight`・`areaWeights(x,z)`（各エリアの重み 0〜1）が読む。
  ゲーム側は同じ関数を `src/terrain-entry.ts` 経由で使い、自然物の配置・採取物・設置判定・音を決める（今の `terrainHeight` と同じ方式）。
- 既存の拠点（-20, 20）とその周り（今の 120×120 の範囲）は**森林エリアとしてほぼそのまま**残す（既存セーブの位置・採取状態・建物を守るため）。
  外側に新しいエリアを足す。既存の座標にいたプレイヤーや建物が、海や地中に入らないこと（§1.4）。
- 推奨配置（提案。ゲーム側で `src/game/worldmap.js` に同じ案を置く予定）：中央＝今の森林・拠点、東＝湖畔→海岸、北東の高地を山麓→雪山、
  南西＝乾燥地→砂漠（オアシス）、北西＝火山（遠景の目印）、南東＝街（集落）。

### 1.2 エリアごとに欲しい地形・表現（色だけで分けない）
| エリア | 地形 | 水 | 目印・特徴 |
|---|---|---|---|
| 森林 | 起伏のある道・倒木の置ける林床 | 川（既存） | 大木・岩 |
| 湖畔 | 湖へ下がる緩い斜面・浅瀬 | 湖（新規・静水） | 葦の群落・砂と粘土の岸 |
| 海岸 | 砂浜・岩場 | 海（地形の端の外まで続く水面） | 波打ち際の泡・漂着物 |
| 火山 | 火山岩・灰地・冷えた溶岩の段 | なし | 遠くから見える山体と噴煙、**活動中の溶岩（発光・歩行不可）**・噴気 |
| 雪山 | 急な斜面と雪の積もった平場 | 凍った池（歩ける／歩けないをゲームに伝える） | 針葉樹・露出した岩 |
| 砂漠 | 砂丘・岩山 | オアシスの池 | 乾燥植物・砂の風紋 |
| 街 | 平らな広場と道路（初期は土の道） | 井戸など | 小規模な集落（原始時代と整合。近代の街並みは段階に応じて差し替え） |

### 1.3 区画（チャンク）
- 地形・水・景観を区画（例：48×48）に分け、主人公の周りを優先して作る。遠方は低い分割・装飾なしの軽量版。区画を離れたら破棄。
- 区画の境目で高さ・法線・色がつながること（ゲームの移動・衝突・採取は区画に関係なく連続した関数で判定する）。
- 初回の読み込み（主人公の周り）と、探索中の読み込み（先読み）を分ける。読み込み中も操作を止めない。
- `GraphicsOptions.quality` に応じて描画距離・影の解像度・景観の密度を変える。ゲームの設定画面から選べるよう、実行中に変える API（例 `setQuality`）があるとよい。

### 1.4 既存セーブの安全
- 既存の 120×120 の範囲で、地面の高さが大きく変わらない（±0.3 以内）こと。変わる場合は差分の表をください（ゲーム側で位置を補正する）。

## 2. カメラ（実行中に変える API）
- 提案：`setCameraView({ yawDegrees?, pitchDegrees?, viewSize? }, { transition?: number, temporary?: boolean })` と `getCameraView()`。
  - 360 度回転（yaw）、上下角（pitch。例 20〜60 度）、ズーム（正投影なので viewSize。例 8〜24）。広角化（透視投影の画角変更）はしない。
  - `temporary:true` は演出用の一時変更（ゲームのユーザー設定は上書きしない。解除で元へ戻す）。
- 地面の下・建物の中へ入らない：正投影なので、カメラの高さを地形・建物より上に保つ処理（必要なら pitch の下限）。
- 遮蔽：手前の建物・樹冠で主人公が完全に隠れるときは、今の遮蔽フェードを回転後の向きでも効かせる。
- ゲーム側の受け口（実装済み）：右ドラッグ・ホイール・2 本指の回転とピンチ・画面のボタン・距離スライダー・「標準に戻す」・設定の保存（`S.camera`）。
  移動方向と主人公の絵の向きは、ゲームが `getCamera()` の実際の向きから計算しているので、回転しても画面基準のまま。
  API がない版では、ゲームはカメラのボタンを出さない（押しても何も起きないボタンを見せない）。

## 3. キャラクター（NPC）
- 提案：`setNpcVisualState(id, { position, direction, moving, spriteUrl? } | null)`。主人公と同じ 4×4 シート・同じ大きさ（ズームで主人公だけ拡大率が変わらない）。
- 主人公と同じく、遮蔽フェード・接地影。遠くの NPC はアニメの更新を間引いてよい。
- 素材：NPC のドット絵シート（案内・住民・職人の 3 種）。**今ある方向は 4 方向（下・左・右・上）のみ。斜め 4 方向はない**（素材不足として記録）。

## 4. 建築モードのプレビュー
- 提案：`setStructurePreview({ type, position, rotationY, valid } | null)`。モデルを半透明（不透明度 0.5 前後）にし、`valid` で緑／赤の色味。影は落とさない・遮蔽フェードの対象外。
- ゲーム側の受け口（実装済み）：今は API がないので、ゲームは通常の建物として置いたモデルの足もとに、画面上の枠（緑／赤）と理由の文を重ねている。

## 5. エリアごとの環境
- 提案：`setEnvironment({ area, weights })`。主人公のいるエリアの重みで、照明・空の色・霧・粒子（雪・灰・砂ぼこり・水しぶき）を混ぜる。
- 暗さ・霧・強いぼかしで形の粗さを隠さない。操作に必要な地面・採取対象は明るく保つ。スマホ（low）では粒子と後処理を減らす。

## 6. 資源タイプ（追加の見た目）
- 葦（湖畔）・漂着物（海岸）・乾燥植物（砂漠）・針葉樹（雪山。既存の景観のコーンを採取ノード化）・火山岩（火山）。
  採取物は**既存データの素材**に対応させる（葦→草、漂着物→木の枝・貝殻、乾燥植物→木の枝、針葉樹→丸太、火山岩→玄武岩）。新しい素材名は作らない。

## 7. 音（ゲーム側で担当）
- 音の素材はない。ゲーム側で Web Audio による環境音（風・水・波・火山の低い音・雪の静けさ・街のざわめき）を合成し、エリアの重みで混ぜる予定。素材があれば差し替える。

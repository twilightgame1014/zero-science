## 1. 【不具合】川の水面が描かれていない（優先度：高）
- `TerrainRenderer.buildWater()` の三角形の頂点の並び順で、面の法線が **下向き（normal.y = -1）** になっています。材質は `side: FrontSide` のため、上から見るカメラでは裏面として省略され、水面が表示されません。
- 実行中にテストの中だけで `material.side = DoubleSide` にすると、青い川がはっきり表示されることを確認しました（ソースは変更していません）。
- 修正案：インデックスの並びを `a, a+2, a+1, a+1, a+2, a+3` に変える（法線が上向きになる）、または `DoubleSide` にする。
- CLAUDE.md の未解決依頼5「水位（0.32）より低い土地が水中色で塗られている」は、この不具合で水面が見えず、川底の色がそのまま見えていることが原因と思われます。
- 水面が表示されたら、川を歩いて渡れる今の状態がより目立ちます。橋（依頼4）と、どこを通れるかの取り決めを一緒に決めたいです。

## 2. 【提案・新API】画面の点から地面を求める公開API（優先度：中）
- ゲーム側は今、カメラの視線を `terrainHeight` に沿ってたどってタップ地点を求めています。実際の地形メッシュとのずれは、**俯角28〜50度・3種類の画面・5地点で最大0.26マス**で、今は問題ありません。
- ただし、1. の修正で水面が見えるようになると、水面をタップしたときに「見えている水面」と「計算上の川底」がずれます。俯角28度では最大で約3.4マスです（(0.32＋1.5)÷tan28°）。
- 提案する契約（後方互換。追加のみ）：
  ```ts
  /** 画面上の点（キャンバス内のピクセル座標）から、描画上の地表の点を返す。表示専用で、通行可否の判定は含まない。 */
  pickGround(canvasX: number, canvasY: number): { x: number; y: number; z: number; surface: 'terrain' | 'water' } | null;
  ```
- ゲーム側は `typeof gfx.pickGround === 'function'` のときだけ使い、なければ今の計算に戻ります（未実装のAPIを無条件では呼びません）。実装されたら `types.ts` と `INTEGRATION.md` に追記をお願いします。

### 不具合・不足（そのまま戻します）
1. **`pauseGraphics` / `resumeGraphics` が入っていない。** 依頼文では「pause-resume を含む積み上げ」とあるが、`feature/graphics-pause-resume-api`（2231183）は 54800d7 の祖先ではなく、`src/graphics/GraphicsEngine.ts`・原本とも `pauseGraphics` が0件。実WebGLで `typeof gfx.pauseGraphics === 'undefined'`。ゲームは従来どおり内部の `stopLoop`/`startLoop` を使っている。2231183 は原本だけの変更なので、Claude 側で取り込むと同一性が崩れるため取り込んでいない。
2. **待機中も歩行コマが動く（歩行アニメーションの不具合の描画側の原因）。** `CharacterRenderer.update` は `moving=false` のとき `Math.floor(animTime*idleFps)%2` で歩行シートの列0と列1を交互に表示する（idleFps 2）。脚の位置が違う2コマなので、止まっていてもゆっくり歩いて見える。実WebGLで、moving=false のコマの表示列が {0,1} を行き来することを記録した。依頼：moving=false では歩行シートを止め、専用の待機コマがなければ直立コマ（列0）に固定する。呼吸の上下動（bob）は残してよい。
3. **遮蔽フェードが採取ノード（`updateResourceVisual` の木・岩）に効かない。** 森の木の多くはゲーム側の採取ノードなので、手前の木の後ろに入ると主人公が完全に隠れる（`/occl2-390.jpg` 相当の画像：前・中・後）。景観の木・建物と同じ仕組みを ResourceRenderer にも。
4. **`highlighted` の強調が大きすぎる。** 木を選ぶと樹冠全体が黄色く光り、主人公や名札を隠す。足元の輪や輪郭の強調にしてほしい。
5. **景観の木・岩（装飾）が残っている。** 採取対象と同じ見た目で、選べず当たりもしない。`decor` 指定（提案パッチ `docs/handoff/patches/graphics-decor-option.patch`）か、歩ける範囲から景観の木・岩を外す対応を相談したい。

## 指摘
1. **描画モジュールの直接編集（ルール違反）**：`src/graphics/GraphicsEngine.ts`・`types.ts` に独自の `setPlayerVisible` と `PlayerVisibilityControl` 型を足している。
   - `src/graphics` は Muse の原本（`threejs-hd2d-graphics/src/graphics`）と一致させる決まり。
   - 同じ名前の公開 API は Muse がラウンド30 で正式に出している。
   - → 修正ブランチで Muse の原本へ戻した（`diff -r` で差 0）。呼び出し側は同じ名前なので、そのまま動く。
2. **組立の段階（S2）が契約 v6 と違う**：PR は v5 の「部分外装の S2」（`visibleAtStage` のノード名の正規表現）。
   - Muse の契約 v6 は「S2＝骨組み＋推進。部分外装の S2 は使わない」とし、機体のメッシュ 90 個を組込枠ごとの一覧（`slotNodes`）で渡している。
   - → `space.js` の `stage` を v6 に、表示を `slotVisible`（`src/space-animation.ts`）に替えた。LOD0・LOD1 とも同じ 90 個のノード名で、一覧がそのまま効くことを確かめた。
3. **宇宙服ディスプレイの位置**：PR は (−6,0,−5) で、宇宙服の組立台とほぼ重なる。契約 v6 の `equipmentPlacement` は (−6,0,−3)。
   - → 表示と当たり判定（`ASSETS.spacePlacement`）を契約の表から作るようにした。
4. **噴射と煙が二重**：
   - PR はゲームの円すいと、GPT の煙の絵のスプライト。
   - ラウンド30 は Muse の `exhaust`・`padSmoke`。
   - → Muse のエフェクトを使い、描画モジュールに `playVisualEffect` がないときだけ PR の表示に戻すようにした。時刻は PR の `FLIGHT`（点火 8.4 秒）に合わせた。
   - **GPT の煙の絵 4 枚は、ふだんは表示されない**（代わりの表示だけで使う）。どちらを正にするかはオーナーの判断を待つ。
5. **`ASSETS.spaceContract` を二度入れている**（マージで起きた）：契約全体を入れる PR の形だけを残した。
6. **打ち上げの時刻**：ラウンド30 の Muse の検品（+3・+5・+7 秒）のあとで、PR が 18 秒の順番再生に変えた。ゲーム側の判断として PR のまま残した。Muse に新しい時刻での見え方の再確認を頼む必要がある。
7. **（後の統合で注意）発射サイトの当たり判定**：18×18 の 1 枚から設備ごとの箱に変わった。
   - サイトの中の空いた所に、ほかの建物を置けるようになる。
   - 街づくり（`feature/game-construction-20261114`）と合わせるときは、サイト全体を「歩けるが建てられない」範囲（nature.js の walk の仕組み）として渡す必要がある。

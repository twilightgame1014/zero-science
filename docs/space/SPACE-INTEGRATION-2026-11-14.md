## 3. 統合のあとに見つけて直した不具合（実画面で確認）
| 不具合 | 原因 | 修正 |
|---|---|---|
| 打ち上げ中、大きな「宇宙へ」パネルが画面を覆い、正式モデルの通路の退避・噴射・上昇が見えない | 搭乗すると宇宙画面へ固定し、パネルは PC で wide・スマホで tall | 演出（カウントダウン〜上昇）の間はパネルを上の細い帯（`data-size="flight"`）にする。宇宙到達とエンディングは従来どおり大きく |
| スマホで搭乗すると 3D が止まったまま演出が動かない | スマホの全高パネル（tall）は 3D を一時停止する。帯に変わっても再開していなかった | パネルの大きさが変わったら一時停止をやり直す |
| 搭乗したのに主人公が搭乗口に立ったまま | 宇宙服の印だけ消していた | 搭乗〜帰還の間は主人公の絵を出さない（描画モジュールの公開 API がないので、ゲーム側でキャラクターの群れの表示だけを切り替え。Muse に API を依頼） |
| e2e:space が再読み込みのあとスキップを押せず止まる | 演出は保存した発射時刻からの実時間で進む。ソフトウェア描画では再読み込みの間に終わっていた（ゲームの不具合ではない） | 飛行中のときだけスキップを押す |
| e2e:space が目標の中の隠れたボタンを押そうとして止まる | 目標に宇宙計画を足したため、同じ属性のボタンが 2 つ | 見えているボタンを押す |
| e2e（play）が保存の版 4 を期待して 1 件失敗 | 宇宙計画で保存の版が 5 に上がった | 期待値を 5 に |

### 何で確かめたか（区別）
- **通常プレイの成立**：自動テストだけ（`tests/space.test.mjs` の数量つき到達。世界の中の移動は含まない。設置と搭乗口への経路は `tests/space-world.test.mjs` が実地形で別に確認）。**人が新しいゲームを最初から宇宙まで遊んだ確認と所要時間は未確認**。
- **画面の確認**：検証モードの所持品と、宇宙計画の検証ボタン（通常と同じ判定を通す：発射サイトの探索と設置・組込・試験・搭乗口へ移動）を使った。
- 実画面はヘッドレス Chromium＋SwiftShader。スマホは画面の大きさとタッチの模擬。**実機・実際の GPU・性能は未確認**。

## 5. 正式モデルの実画面確認（PC 1280×720・スマホ縦 390×844）
- 段階：S0（発射台・塔・管制・設備）→ S1（骨組み）→ S2/S3 → S4（外装・カプセル・通路）。**組み込んでいない部品は先に出ない**（S0 で機体なし、S1 で骨組みだけ）。
- 4 方向（向き 32°・122°・212°・302°）と低い角度（14°・10°）で、台・塔・機体の接地を確認。台の下面は地面の高さ（発射サイトの中心）にあり、浮き・埋まりは見えない。機体は台の保持リングの中に立つ。
- 演出：カウントダウン（パネルは帯）→ 通路と塔の退避 → 噴射 → 上昇（カメラが追う）→ 宇宙到達 → エンディング。PC とスマホ縦で撮影。
- 宇宙服：男女どちらでも仮の印が出る（実画面）。主人公の選択は変わらない（テスト）。**仮の箱と透明な球で、見た目は粗い**。
- 未確認：全クリップの全姿勢（ハッチの開閉の途中・保持アームの外れ方）の目視、透過の並び、LOD0（同梱なし）、実機の FPS。

## 6. 残っている不具合・課題
- 宇宙服は仮表示（男女の正式 8 方向シート待ち）。
- 追加 55 品目のアイコンは絵文字の仮表示。テクスチャ原画は未制作。一覧は `docs/space/MISSING-ASSETS.md`。
- Codex の追加品目の説明は定型文が多い（`more` がほぼ同じ文、`yomi` が漢字のまま）。GPT の科学レビューと合わせて書き直す。
- 発射サイトの候補探索は主人公の周りから円形に探すだけ。候補が遠いことがある（実地形では (100,100) など）。
- 演出の上昇はソフトウェア描画では機体がカメラより先に画面の上へ出ることがある（低 FPS で追従が遅れるため。実機では未確認）。
- 検証モードではカメラの調整表示がスマホで目標の枠と重なる（検証モードだけ）。
- 実習②〜⑧の一部は e2e ではテストが状態を直接書いている（UI での全実習の通しは、Codex の記録では手動で実施。このブランチでは自動では実習①だけ）。

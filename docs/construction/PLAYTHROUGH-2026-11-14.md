## 1. 画面の操作だけで遊んだ確認（`tests/e2e/playthrough.mjs`）
プレイヤーと同じ入口だけを使った：
- 対象をタップして近づく（`selectAndGo`。マップのタップと同じ）
- 採取ボタン
- パネルのボタン（工作・建築・現場・研究室）

採取と建築の判定には手を入れていない。描画は偽のモジュール（3D の見た目は対象外）。

| 区間 | PC 1366×768 | スマホ幅 390×844 |
|---|---|---|
| 枝・小石・火打ち石 → 石のナイフ | タップ 13・採取ボタン 0・画面の操作 3 | 同じ |
| つる・草 → 糸 → 作業台（予定地 → 現場へ → まとめて運ぶ → 施工） | 作業台の施工の待ち 2.9 秒 | 同じ（建築はメニューの中。メニューを開く 1 回が増える） |
| 火おこし棒 → たき火（2 工程） | 待ち 1.9 秒＋2.0 秒 | 2.0 秒＋2.0 秒 |
| 研究室で枝を燃焼（目標 6 達成） | 施工で枝を使い切ったので、枝を 2〜3 本拾い足した | 同じ |

- 数値はこのスクリプトの 1 回の実行で、人のプレイ時間ではない。
- 歩いた距離は「タップした所までの直線」の合計で、実際の経路はこれより長い。
- 実時間（偽の描画で 77〜80 秒）は、人が迷う時間・読む時間を含まない。**所要時間・快適さは未計測**。

### 見つけたことと対応
| 見つけたこと | 対応 |
|---|---|
| 進行不能・操作不能はなかった。予定地の画面は離れていると「運ぶ」が押せず、理由と「現場へ行く」が出る | そのまま |
| 宇宙計画の製作で、足りない物が文字だけ（「設備：作業台」）。建物の設備が未完成でも、どこへ行けばよいか分からない | 足りない物ごとにボタンを付けた（下の 2.） |
| 発電機は現地に建てる設備なのに、宇宙計画の作り方・打ち上げ条件からは昔の工作の説明にしか行けない | 建設の状態と「建設する／現場を開く」を出した |
| 完成した設備の画面で、次に何をするかが出ない | 「次に使う所」（研究室・工作・宇宙計画の製作）を出した |
| スマホのメニューの「建築」の説明が古い（「作った家や設備を好きな場所に置く」） | 建設の決まりでは「設計図を選び、現地に建てる（予定地→資材を運ぶ→施工）」 |
| 施工で枝を使い切ると、目標 6（枝 2 本の燃焼）の前に拾い足しが要る | 普通の遊び方の範囲。案内の文は変えていない |
| 完成・新発見のお知らせ（最大 3 枚）が、現場の画面の見出しに重なる | 未対応（読めなくはない。表示の位置は相談） |

## 2. 案内（建築と宇宙計画の製作）
- **宇宙計画の製作のカード・作り方の画面**：足りない物をボタンにした。
  - 建物の設備：状態（未着手／予定地／資材の搬入中／施工中）と工程（例「予定地・工程 0/2」）、「現場を開く」か「建設する」
  - 実習：「実習へ」（その実習を選んだ実習の画面へ）
  - 材料・作る設備・道具：「作り方・原料」「作り方を見る」
- **カードの状態**：「設備の建設待ち」「設備を施工中」を足した（以前は「設備不足」だけ）。
- **未完成の設備**：生産には使えないまま（`SPACE.startCraft` は施工中の発電所では始まらない。e2e で確認）。
- **工作の画面**：現場への入口に状態と工程を出す（例「現場を開く（予定地・工程 0/2）」）。
- **完成した設備の画面**：「次に使う所」を出す。設備の使い道から、研究室・工作・宇宙計画の製作のうち使える所だけ。
- 試験待ちと打ち上げ条件の不足は、既存の「確認する」（試験・組立・発射サイトへ）のまま。発電機だけは建設の入口にした。

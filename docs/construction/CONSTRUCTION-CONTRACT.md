# 街づくり・現地建設の契約（Claude ↔ Muse、2026-11-14）

建物も道も、プレイヤーが場所と向きを決め、資材を現地へ運び、工程ごとに施工して完成させます。
ゲームは今、**仮表示**（杭・縄・資材の山・足場・色の板の道）で最後まで動きます。この文書は、正式な工程別の見た目を受け取るための契約です。
仮表示を正式な見た目の完成として扱うことはしません。

## 座標
- 原点は地面の上の中心（底面の中心、Y=0 が地面）です。+Z が正面（入口・作業点の側）、Y が上、1 単位＝1 マスです。
- 向きは three.js の `rotation.y` で、プレイヤーが 15 度単位で決めます。
- 地面はならしません。建物は中心の地面の高さに置きます。
- 大きな建物（大型工場・化学研究所）は、占有範囲の中の高低差を 0.6 まで許します（`maxRise`）。モデルの土台は、この程度の差を見せないつくりにしてください（土台の側面を 0.6 下まで伸ばすなど）。

## Muse が埋める欄（`construction-assets.json` の `museFields`）
### 建物 24 種
- `stageNodes`
  - 工程の番号（`stages[].index`）ごとに、表示するノード名の一覧です。例：`{"0":["Base"],"1":["Base","Frame"],"2":["Base","Frame","Wall","Roof"]}`
  - 完成した姿は最後の工程の一覧です。足場などの「建設中だけの部品」はノード名を `Scaffold_*` にしてください。完成した建物では、ゲームが隠します。
  - 形の決め方は、ロケットの契約 v6 の `slotNodes` と同じです（GLB からの機械抽出をお願いします）。
- `roadConnectors`
  - 道がつながる点のローカル座標の一覧です（例：`[[0, 2.0]]`）。
  - ゲームは今、入口（`entrance`）か作業点（`operate`）の前 0.8 マスを接続点にしています。
- `lod`：LOD1 の有無と、形・寸法が LOD0 と同じかどうか。
- `materialSlots`：材質の名前の一覧（テクスチャを貼る準備）。
- `status`：未着手／制作中／納品済み。

### 道 3 種（土・砂利・石敷き）
- `tileTexture`：2×2 マスの板に貼るテクスチャ（タイルあり）。
- `edgeTreatment`：道の縁の見た目（草との境目）。
- `joinPieces`：直線・曲がり・T 字・十字・行き止まりの部品が必要かどうか。今は四角いマスを並べています。
- 道は**歩ける面**です。当たり判定は付けません。高さは地面に沿わせ（今は +0.05）、ちらつかないよう polygonOffset を使っています。

## いまの仮表示（`src/construction-visual.ts`）
| 状態 | 仮表示 |
|---|---|
| 予定地 | 占有形状の四隅の杭と縄、入口の小旗。壁にはなりません（歩ける）が、ほかの建物は置けません |
| 搬入中 | 上に加えて資材の山（運んだ割合で 1〜6 個） |
| 施工中 | 足場の柱と、工程の進みに合わせて高くなる仮の壁（壁になります） |
| 完成 | 既存の正式モデル（`structures.json`・街の GLB） |
| 道（完成） | 種類ごとの色の板を地面に沿わせる（1 メッシュにまとめる） |
| 道（予定） | マスの縁の線 |

## 建設のきまり（ゲーム側。変えるときは Claude に連絡）
- 流れは `planned`（予定地）→ `supplying`（搬入中）→ `constructing`（施工中）→ `completed`（完成）です。
- 予定地の ID は `cs-<番号>` で、セーブの `cons.inst` に入ります。
- 資材は現地の 2.6 マス以内から運びます。後の工程の分も先に運べます（必要数まで）。
- 取消・解体のとき：
  - 使っていない資材は全部戻ります。
  - 施工済みの工程は、返却表（`salvage`）の分だけ戻ります。
  - 返却表がない建物は、施工済みの分は戻りません。
- 同じ建物はいくつでも建てられます。ただし設備としては「使える」だけで、生産量は増えません。
- 屋台と果物かごは通常のゲームでは建てません（売り買い・食べ物の仕組みがないため）。植木鉢と旗は「飾り（働きなし）」と書いて建てられます。

## Muse の納品（2026-11-14、ブランチ feature/graphics-city-construction-final）

`construction-assets.json` の `museFields` を全 24 建物・道 3 種について埋めた。追加素材は `assets/construction/` に置く（完成建物の再制作はしていない）。

### 工程表示の適用規則（stageNodes の読み方）

- `stageNodes` のキー `k` は、工程 `k` が**完了した直後**に表示するノードの一覧（累積）。完成時は最後の工程の一覧がそのまま完成した姿になる。
- 工程 `k` の**施工中**は、一覧 `k-1`（`k=0` のときは建物ノードなし＝予定地キットのみ）に、下記の足場と資材置きを加えて表示する。部品が宙に浮かないことは、全建物・全工程について部品の支持関係を数値検査済み。
- 完成した建物では `Scaffold_*` を必ず隠す（足場は建物の GLB には含まれず、共有キットから別に置く）。
- `ContactShadow`（接地影の板）は最後の工程の一覧にだけ含めた。途中の工程で出すと、傾斜地で板が浮いて見えるため。完成時の見た目は現在の正式モデルと同一になる。
- 広場（plaza）の工程 0「整地」は一覧が原点ノードのみ（＝石敷きはまだ無い）で正しい。

### 予定地キット（assets/construction/models/construction-site.glb、960 tris）

単位 1×1 の部品集。占有範囲 `w×d` に対してゲーム側で配置する（建物の回転に追従）。
- 杭 `stakePP/PM/MP/MM`：`(±(w/2+0.5), 0, ±(d/2+0.5))`（符号は名前の P/M 順＝X・Z）。
- 縄 `ropeX_P/M`：`(0, 0, ±(d/2+0.5))`、`scale.x = w+1`。`ropeY_P/M`：`(±(w/2+0.5), 0, 0)`、`scale.z = d+1`。
- 輪郭 `outlineX/Y_*` は縄と同じ配置（地面の輪郭線）。
- 円形の占有範囲では、杭と縄を半径 `r+0.5` の 8 点に置き換える（仮表示の `outline()` と同じ点）。

### 足場キット（assets/construction/models/scaffold-kit.glb、1,272 tris、共有 1 点）

部品は単位寸法で、ゲーム側が複製して変形する（ノード名で引く）。
| ノード | 原点 | 形 | 変形 |
|---|---|---|---|
| `Scaffold_Post` | 底面中心 | φ0.14・高さ 3.0 の柱（縄の結束 2 か所つき） | `scale.y = 必要高さ/3.0` |
| `Scaffold_Beam` | 中心 | 長さ 1・0.09×0.12 の横木 | `scale.x = 間隔` |
| `Scaffold_Plank` | 中心 | 長さ 1・幅 0.34・厚さ 0.05 の足場板 | `scale.x = 間隔` |
| `Scaffold_Brace` | 中心 | 長さ 1・0.07 角の筋交い | 区間の対角に回転して `scale.x = 対角長` |
| `Scaffold_Ladder` | 底面中心 | 幅 0.48・高さ 3.0 の梯子 | `scale.y = 必要高さ/3.0` |
配置の規則：占有範囲を 0.45 広げた外周に、柱を角と 2.2 以下の間隔で立てる。高さは工程ごとに上がり、施工中の工程 `k`（全 `N` 工程）では `(k+1)/N × (建物の高さ + 0.6)` を上限に、2.2 ごとの段で横木を回す。足場板は最上段の入口側ともう 1 面に敷く。筋交いは外周の区間に 1 つおき。梯子は入口側の角に 1 本。地面の傾斜では柱ごとに底を地面へ合わせる（仮表示の足場と同じ扱い）。LOD は持たない（部品が小さいため）。

### 資材置き（assets/construction/models/pile-*.glb、共有 5 点）

搬入の進み具合で置く資材の山。形は `pile-lumber`（材木）／`pile-stone`（石）／`pile-sacks`（袋）／`pile-metal`（金属材）／`pile-crated`（箱詰め）の 5 種で、原点は底面中心。置き方は仮表示と同じ規則（現場の +X 側に、運んだ割合で 1〜6 個を並べる）を正式モデルに差し替える。資材の種類の対応は、その現場で未搬入の資材から選ぶ（木材→lumber、石材→stone、袋物→sacks、金属→metal、その他→crated）。

### 道の適用仕様（museFields の補足）

- テクスチャは 1 セル（2×2 m）に 1 回繰り返す。道路メッシュの UV はセルごとに (0,0)–(1,1) を割り当てる（今の `buildRoads` の分割頂点に、セル内の相対位置をそのまま UV にする）。石敷きの目地はセル周期でそろう。
- 縁のフェード：セルの外周 0.18 m の範囲で、頂点色を地面の色へ寄せて 12% 暗くする。これで草との境目を作る。端部・曲がり・分岐も同じフェードで処理でき、接続部品（joinPieces）は不要。
- 斜面は今の 4 分割の地面追従のままでよい（テクスチャは面に貼るだけなので隙間は出ない）。
- 法線テクスチャ（`*_n.png`）は任意。使う場合は `normalScale` 0.5 程度から。
- ノード名の照合：three.js の GLTFLoader は読み込み時にノード名から `.` などを取り除く（例：`post.001` → `post001`）。`stageNodes` の名前は GLB 内の正式名で書いてあるので、照合する側は両方を同じ規則で正規化すること。全 24 モデルについて、正規化後の名前の衝突が無いことを確認済み。

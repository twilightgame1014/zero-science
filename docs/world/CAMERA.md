# 探索カメラ（ドラッグ操作）

更新：2026-11-08（Claude）。ブランチ `feature/game-drag-camera`（土台 `feature/game-round22`）。`src/graphics` は変更していない。

## 1. 操作
| 入力 | 動き |
|---|---|
| マップの何もない所を1本指でドラッグ（スマホ・タブレット） | 左右＝主人公を中心に水平に回る（360°連続）。上下＝見下ろし角 |
| マップの2本指のピンチ | 広げる＝近づく、すぼめる＝離れる（回転はしない） |
| 左ボタンのドラッグ（PC）・右ボタンのドラッグ | 同じ回転 |
| ホイール | 近づく・離れる |
| 短いタップ・クリック | 今までどおり移動・採取・人と話す・建築の候補を動かす（`tapAt`） |
| 「🎥 視点を戻す」（右上の小さなボタン・設定画面） | 標準の角度と距離へなめらかに戻る（短い向きに回る。感度は残る） |

- 回転の向き：右へドラッグすると景色が右へ回る（主人公の手前の地面が指と同じ向きに動く。実WebGL で確認）。下へドラッグすると上から見る角度になる。
- 注視点は主人公の足もと（描画モジュールが追従。歩行の上下動は含まない。地形の高さにはなめらかに追従）。自由な平行移動はしない。
- 初回だけ「ドラッグで視点変更／2本指でズーム」（PC は「ホイールでズーム」）を出す（`S.flags.camHint`）。
- 撤去したもの：回転・上下・近づく・離れるのボタンと距離のスライダー。

## 2. 指の担当（競合の防止）
- 担当は pointerId ごと（`W3.ptrs`）。マップ（`#w3`）の地面で始まった指だけがカメラ・タップの担当で、`setPointerCapture` で離すまで担当が変わらない（途中で UI の上へ行ってもカメラのまま。離してもその UI は押されない）。
- スティック・行動ボタン・下部のタブ・右上のボタン・パネル・名札（`.w3lab`）で始まった指は担当外（途中でマップの上へ動いてもカメラは動かない）。
- ピンチはマップで始まった2本の指だけ（スティックの指とは組み合わさない。3本目は無視）。左手でスティック、右手でマップを回せる。
- 押した直後は「タップ候補」。`CAM.tapSlop`（8 CSSピクセル）以上動いたらドラッグ。ドラッグ・ピンチをした一連の操作（全部の指を離すまで）からはタップを出さない。450ミリ秒以上押したままもタップにしない。
- 2本→1本：残った指の基準位置を取り直す（離した瞬間に回らない）。1本→2本：ピンチ中は回転しない。
- 解除：pointerup・pointercancel・lostpointercapture・blur・visibilitychange（非表示）・pagehide・パネルや案内を開いたとき（`haltField` → `W3.ptrReset`）。解除したらカメラはその場の角度で止まる（慣性なし）。
- ブラウザ：マップ（`.stage`）は `touch-action:none`（スクロール・ピンチ拡大と競合しない）。iOS の `gesturestart`/`gesturechange` はマップの上だけ止める。文字選択・長押しメニュー・画像のドラッグは従来の規則（入力欄とパネルのスクロールは止めない）。

## 3. 角度・距離の定義と範囲
- 見下ろし角＝水平から下への角度。0°＝注視点と同じ高さ、70°＝上から70°。描画モジュールの `pitchDegrees` も同じ定義（`offset.y = sin(pitch)`。極角ではない）ので換算はしない。
- モジュールの範囲は第24ラウンドから 0°〜72°（それより前は 12°〜72°）。ゲームの範囲は 0°〜70°。ただし近い面が地面を切る角度へは下げない（§4）。
- 水平の角度（yaw）は連続した値で持ち（何周しても 359→0 で逆回りしない）、渡すときだけ 0〜360。
- ズームは正投影の表示範囲（viewSize）。標準×0.55〜×1.9。カメラ本体の距離（`distance`、第24ラウンド。10〜260、希望 90）は見え方の大きさを変えず、どこまで手前を描くかだけを変える。

## 4. 高さの固定・低い視点・衝突（2026-11-08 改訂）
### 4.1 勝手に上下していた原因（修正前）
1. 描画モジュールが毎フレーム、注視点の高さを主人公の足もとの地面へなめらかに合わせていた（`GraphicsEngine` の loop：`setTarget(x, z, getGroundHeight(x, z))`）。坂・起伏でカメラ全体が上下した。
2. ゲームの `camNeed`（2026-11-08 の前の版）が、地形・建物が主人公とカメラの間に入ると見下ろし角を自動で上げていた（山道で 33°→66°）。
3. 低くできなかった原因：モジュールの下限 12°、主人公を画面の少し下に置くずらし（`anchorOffset` 0.09×表示範囲＝約1.2マス上を注視）、2. の自動の上昇（平地でも 90 マス先の起伏で 12° が 27° になっていた）。
※ 歩く絵の上下動はもともとカメラに入っていない（モジュールは足もとの位置だけを見る）。

### 4.2 今の仕組み
- 基準の高さ `W3.cam.base`：読み込み・瞬間移動・地域移動・「視点を戻す」のときだけ、その時の主人公の足もとの高さにする（`camRebase`）。毎フレームは決め直さない。
- 狙う注視点：水平は主人公（モジュールのなめらかな水平の追従）、高さは `base + 0.3×(1−w)`、画面の下寄せは `anchorOffset×w`（`w`＝見下ろし角 0°〜25° でなめらかに 0→1）。標準の角度（32°）では以前の平地の見え方と同じ。
- 打ち消し：モジュールの注視点の高さ `cur` をカメラの位置から逆算し（前の2コマから1コマ先を予測）、`setViewportInsets` の上下の差（画面の上下のずらし `s`）と `distance` で、狙う注視点・カメラ本体の位置に合わせる。正投影なので絵はまったく同じになる。
- 角度・ズームが変わるのはユーザーの操作中だけ（ドラッグ・ピンチ・ホイール・視点を戻す、とそのなめらかな続き）。歩いている間は変えない。
- 衝突（正投影なので「カメラ本体の面＝近い面より手前は描かれない」）：
  1. 近い面の四角（表示範囲×画面の縦横比、下から上へ 4 段×7 点）が地形・建物（占有範囲の上は地面＋建物の高さ）＋0.3 より上にある距離を、90→75→60→45→32→22→15→10→110→140 の順に探す（140 より遠くには置かない：正投影では本体より手前の物がすべて重なり、遠くの山が画面を覆う）。主人公からカメラの向きへの線が隠れない距離を優先、なければ近い面だけ満たす距離。
  2. 操作中に置けない：回転・ズーム・角度をそこで止める（角度は二分探索で置ける所まで）。操作が終わったら、止まった値を新しい希望の値にする。
  3. 歩いている間に置けない：距離を変える。それでも駄目なら水平の追従を止める（`setCameraTarget` で直前の安全な位置。置けるようになったら戻す）。
  4. 距離を縮めるのはすぐ、戻すのは 0.4 秒続けて置けたときだけ（出たり消えたりしない）。自動の上昇はしない。
- 木は描画モジュールの遮蔽フェードで薄くなる（衝突には数えない）。

### 4.3 検証用の表示
検証モードか URL に `?camdebug=1` を付けると、左下にカメラ本体のY・注視点のY（基準）・見下ろし角（実際／希望）・距離・制限の有無を出す。`window.__GAME__.cam.debug()` でも読める。

## 5. 主人公の向き（2026-11-08 第23ラウンドの8方向を取り込み）
- `W3.face`＝ワールドの向き。進もうとしている向き（スティック・キーの入力、クリック移動の次の通過点）で変わり、壁で滑っても止まっても変わらない。カメラを回しても変わらない。`S.pos.face` に保存（古いセーブは画面基準の `dir` から換算）。
- 絵の行は「向き − カメラの画面下方向」の相対角を 8（または4）セクターに分けて選ぶ。今の行の中心から ±(半セクター＋6°)（4方向は＋10°）を超えたときだけ変える。静止中もカメラを回すと見える面が変わる。
- 主人公のシートは男女とも8方向（Muse 第23ラウンド）。ただし**描画モジュールの今の版はカメラ角の約27%で行が固まる**ので、起動時の自己点検（`HD2D.diag8Check`）に通らない間は、シートの上4行を切り出して4方向で出す（CLAUDE-TO-MUSE §22-1。直った版なら自動で8方向）。
- 移動（スティック・キー）はカメラの水平の向きが基準（画面の上＝奥）。見下ろし角で速さは変わらない。斜めは正規化（縦横より速くならない）。歩行は実際に進んだ量で決める（止まる・壁で進めない＝`moving=false`）。歩く速さ `speed` も渡す（モジュールが使うのは §22-2 の対応後）。

## 7. 検証
| 項目 | 環境 | 結果 |
|---|---|---|
| typecheck・build・`npm test`（全174物質） | Node 22 | 合格 |
| `npm run e2e`（偽の描画モジュール） | Playwright Chromium（PC 1366×768・タッチのエミュレーション 390×844） | 205件 合格（カメラ関連 約30件：下の 1〜12 のほとんど） |
| 実WebGL（本物の描画モジュール） | ヘッドレス Chromium＋SwiftShader、PC 960×540 とタッチのエミュレーション 390×844、低品質 | 下表 |

実WebGL の結果（SwiftShader は毎秒2コマ前後なので、なめらかさ・手ざわりは判定していない）：
1. 左右に何周も：左へ約4.9周。毎回同じ向きに進み、0°をまたいでも逆回りなし。
2. 見下ろし角：下へドラッグで 70° で止まる。上へで 12°（モジュールの下限）で止まる。
3. ピンチ：広げると 13→7.15 に近づく。タップは出ない（タッチのエミュレーション）。
4. 1→2→1本：e2e で確認（実WebGL では未実施）。
5. 左手でスティック、右手で回転：約3秒で 28.8 マス歩きながら 49° 回った。ピンチにならない（タッチのエミュレーション）。
6. UI からの操作でカメラが動かない：e2e で確認。
7. ドラッグ後に移動・採取しない：実WebGL でも移動先なし。短いクリックは狙った地面へ（差 0.0002）。
8. 衝突：山の登山道で山側にカメラ → 見下ろし角が 12→36° に上がり、足まで見える（線の余裕 1.96 マス）。谷側へ回すと 29→1.9 へなめらかに戻る。小屋の陰 → 53° に上がり、主人公が小屋の手前に見える。森の低い角度は木が薄くなる（モジュール）。
9. 男女の向き：ワールドの向きを固定してカメラを45°ずつ回すと、正面→（境界は前の行のまま）→左→背中→右と変わる（左右の取り違えなし）。斜めの絵はない。
10. 画面回転（縦→横）・非表示→復帰：途中の指は手放され、その後の指の動き・離しで回らない。描画は再開する（タッチのエミュレーション）。
11. PC：左ドラッグ・右ドラッグ・クリック・ホイール（13→8.26、最大 24.7 で止まる）。
12. 保存と復元：角度・見下ろし角・距離・感度が再読み込みで戻る。壊れた値は補正（e2e）。

## 8. 未確認・残り
- **スマホ・タブレットの実機では確かめていない**（上のタッチは PC のタッチのエミュレーション）。iPhone Safari のピンチ拡大の抑止（gesture イベント）・実機の手ざわり（感度・平滑化の強さ）・実機の FPS。
- 見下ろし角 0°〜11° は使えない（モジュールの下限 12°。§21-1）。
- 斜め4方向の絵がない（§21-3）。
- 距離を縮めて障害物を避ける方式はモジュールの口がないため、角度を上げる方式だけ（§21-2）。
- 水平に近い角度で世界の端を見ると、外は海の水面が地平まで続く（区画の外の地面が抜けて見えることはなかった：(165,60) で外向き 12°）。0° は試せていない。

## 9. 高さの固定の検証（2026-11-08、修正前＝`feature/game-8dir`、修正後＝`feature/game-camera-height`）
環境：ヘッドレス Chromium＋SwiftShader（ソフトウェア描画）、960×540、低品質、検証モード。数値は描画モジュールのカメラ本体の位置を毎コマ記録したもの。
SwiftShader は毎秒2〜5コマなので、なめらかさ・手ざわりは判定していない。スマホ・PC の実機では未確認。

| 条件 | 修正前 | 修正後 |
|---|---|---|
| 1. 平地で下げられる一番低い角度（拠点、ドラッグで上へ大きく） | 希望 12° に対し実際 26.9°（自動の上昇） | 6.6°（ここ・この向きで近い面が地面を切らない下限。止まった値が新しい希望になる）。注視点は基準＋0.59 |
| 2. 起伏（地面の高さの差 1.0）をカメラを触らず歩く（32°） | カメラの高さ ±4.8、俯角 32〜35° | カメラの高さの幅 0.11、俯角・注視点は一定 |
| 2b. 低い角度（4.3°）で起伏を歩く | カメラの高さの幅 15.2、俯角 17〜28° | 0.18、俯角一定（一時的に「水平の追従を止めた」あり） |
| 3. 登山道を上る（地面の差 10.1、32°） | カメラの高さの幅 39.1、俯角 33〜66° | 0.61、俯角・注視点は一定 |
| 3. 下る（地面の差 9.5） | 37.6、32〜64° | 0.38、一定 |
| 4. 低い角度（4.5°）で一周回す | 俯角 18.6〜28.8°（自動の上昇） | 俯角一定。カメラの高さの幅 0.03。置けない向きでは回転を止める |
| 5. 建物（小屋・研究所）の近くで低い角度（6°）一周 | 俯角 21〜63°（自動の上昇） | 俯角一定。距離を 90／110／140 に変えて近い面を建物の外へ（本体の高さは距離に応じて変わる） |
| 5. 斜面の途中で低い角度（6°）一周 | 俯角 15〜43° | 俯角一定。「見通しなし」（斜面が主人公の手前）の向きあり |
| 6. 坂の途中で「視点を戻す」 | — | 基準がその場の足もと（10.20）になり、その後は動かない（幅 0.000） |
| 7. 低い角度でズーム（ホイール） | — | ズームの分だけ変わる。近い面が地面を切る所へは入らない |

- 修正後に残る上下（0.1〜0.6）は、モジュールの注視点の次のコマを予測するずれ（2つの描画ループのコマの時間の違い）。登山道で1コマずつ比べると、予測あり 0.17、予測なし 0.42（480×270、毎秒約4.5コマ）。毎秒60コマの実機では1コマの高さの変化そのものが小さいので、もっと小さくなるはず（未確認）。
- 正投影の性質で、低い角度では視線の手前の草・やぶが主人公に重なる。カメラ本体を 140 より遠くに置かないのは、遠くの山が手前に描かれて画面を覆うため。
- 高さを固定したので、標準のズームでは約7〜8マス登ると主人公が画面の上へ出る（仕様どおり。「視点を戻す」かズームで戻す）。

# M3-02 植物アセット（Muse、2026-11-15）

用途と姿が異なる植物8種×2シルエット＝16アセット。契約は `plants-contract.json`、
不足テクスチャの依頼は `GPT-TEXTURE-REQUEST.md`、生成は `tools/build_plants.py`、
実測は `tools/measure_glb.py`、契約生成は `tools/gen_contract.py`。
編集可能な元データは `source/*.blend`（LOD0 のシーン）。

状態区分：**モデル完了／UV・材質仕上げ完了（GPT 原画適用済み）／統合待ち**。
ゲームへの導入は未実施（生成・採集・再生・セーブは Claude 担当）。
異星での正式名称・採集レシピ・収量はここでは決めていない（名称は制作上の分類）。

## UV・材質仕上げ（2026-11-15、契約 v2）

- 全32 GLB の全プリミティブに TEXCOORD_0 を設定済み（葉メッシュのパラメトリック
  UV を `tools/build_plants.py` の leaf_mesh に追加して再生成。寸法・三角形数・
  ノード名・材質名は旧版と完全一致を実測）。針葉 needleA は UV 崩壊も併せて解消
- 加工済み共有テクスチャは `textures/`（原画は `gpt-art/` に未加工で保存、
  加工記録は `textures/processing-record.json`、UV テンプレートは
  `textures/uv-templates/`）。GLB への同梱はしない
- スロット↔画像の機械可読対応は `plant-materials.json`、接続コードは
  `plant-materials.mjs`（材質名で差し替え。採集割当てには触れない）
- 透過方針：ジオメトリは不透明のまま。単葉テクスチャは alphaTest 0.45 で
  ジオメトリ輪郭との交差に切り取る（黒い板・広い半透明面を作らない）。
  needleA のみ不透明合成（松の芯球に穴を開けないため）。詳細は
  plant-materials.json の alphaPolicy

## 制作方針

- 全アセットがジオメトリ葉（折りのある葉カード）＋幹→枝→葉の構造。緑球の樹冠は不採用
- テクスチャは GLB に同梱しない。GPT 原画の加工済み共有画像を材質名
  （スロット）経由で後付けする（重複同梱なし）。未適用スロットはフラット
  パレットのまま（理由は plant-materials.json の untexturedSlots）
- ジオメトリは全て不透明。葉テクスチャの抜きは alphaTest の交差方式で、
  半透明ブレンドを使わないためソート乱れは発生しない
- 表示状態はノードグループの表示切替：木＝`state_standing`／`state_stump`、
  草本＝`state_full`＋`parts_fruit`（花・実の有無）／`state_low`、
  竹・葦＝`state_full`／`state_cut`
- 原点は株元中心、接地は y=0（根張りが −0.05 まで沈むので平地で浮かない）

## ゲーム追加時の容量見積もり

- 全16アセットを LOD0+LOD1 でそのまま単一ファイルへ同梱すると +6.68 MB で、
  現行 dist（約13.5〜15.5 MB）では 16 MB 上限に収まらない
- 圧縮同梱（ロケット線の gzip 方式）では実測比で約6割、+約4 MB 前後の見込み。
  それでも上限に近いため、エリア別・種別の段階導入か、既存の軽量化パイプライン
  （tex 共有）前提の導入計画が要る。これは Claude 側の統合判断として申し送る
- 本ラウンドではゲームコードに接続していないため、dist 容量は不変
